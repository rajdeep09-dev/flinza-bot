3.1 UNSUBSCRIBE TOKEN SALT IS HARDCODED AND PREDICTABLE [HIGH]
    File: outreach_engine.py, line 1228
    ```python
    salt = "flinza_unsub_salt_2026"  # ❌ Everyone can see this in source code
    ```
    Problem: Since the salt is in the source code, anyone can:
    - Generate valid unsubscribe URLs for any email
    - Force-unsubscribe any lead from your campaigns
    - Manipulate unsubscribe tracking

    ```python
    import secrets
    ```

    And add UNSUB_SALT to .env.example

    File: outreach_engine.py, line 1239

    Problem:
    - The lead's email address is visible in the URL
    - Gets logged in server access logs
    - Gets stored in browser history
    - Violates GDPR (personal data in URL)
    - Gmail/Outlook may flag emails with email-in-URL as suspicious
    
    FIX: Remove email from URL, look up by token only:

    ```python
    unsub_url = f"{clean_base}/u/{token}"
    ```

3.3 HASH() BUG STILL EXISTS IN launch_campaign() [MEDIUM]
    File: outreach_engine.py, line 704
    ```python
    seed = hash(lead["email"]) % 10000  # ❌ NOT fixed!
    ```
    Problem: The `personalize()` function was fixed to use hashlib, but
    `launch_campaign()` still uses the broken hash(). This means:
    - Campaign launches produce different spintax results on every restart
    - Lead email fingerprints are not reproducible
    - A/B test results are unreliable
    
    FIX (line 704):

    ```python
    import hashlib

    ```

3.4 SMTP PING TO RANDOM MX SERVERS — ABUSE RISK [MEDIUM]
    File: email_verifier.py, lines 72-76
    ```python
    with smtplib.SMTP(mx_host, 25, timeout=timeout) as smtp:
        smtp.ehlo_or_helo_if_needed()
        smtp.mail(sender_email)
        code, msg = smtp.rcpt(target_email)
    ```
    Problem:
    - Opens port 25 connections to ANY random MX server on the internet
    - Many mail servers block or rate-limit unsolicited RCPT TO checks
    - This is exactly what spam blockers detect (SMTP probing)
    - Can get YOUR IP flagged if you run this at scale
    - The sender_email "verify@flinza.io" doesn't exist — causes 550 errors
    
    This is dangerous because:
    1. Many domains block port 25 entirely
    2. Gmail/Outlook/AOL actively rate-limit SMTP ping attempts
    3. Your server IP could get added to RBLs (spam blocklists)
    
    FIX — Remove or gate the SMTP ping:
    ```python
    def ping_smtp_mailbox(mx_host, target_email, timeout=5):
        """
        WARNING: This probes external mail servers on port 25.
        Use ONLY in offline mode or with explicit user consent.
        For production, rely on DNS MX + disposable check only.
        """
        # Option 1: Skip SMTP ping entirely, rely on DNS
        return {"valid": True, "status": "mx_verified", "message": "MX records valid"}
        
        # Option 2: Only probe known-safe domains
        SAFE_PROBE_DOMAINS = {"gmail.com", "yahoo.com", "outlook.com"}
        if mx_host not in SAFE_PROBE_DOMAINS:
            return {"valid": True, "status": "mx_only", "message": "External MX skipped"}
    ```

3.5 COOLDOWN STATE IS IN-MEMORY ONLY — LOST ON RESTART [MEDIUM]
    File: outreach_engine.py, line 280
    ```python
    self._cooldowns: Dict[str, float] = {}
    ```
    Problem: When the bot restarts, all cooldown states are lost.
    This means:
    - After a crash/restart, all mailboxes are immediately available
    - If you were rate-limited before the crash, you'll hit the limit again
    - Undermines the failover protection
    
    FIX: Persist cooldowns to SQLite:
    ```python
    def trigger_cooldown(self, email, minutes=15, reason=""):
        cooldown_until = time.time() + (minutes * 60)
        self._cooldowns[email] = cooldown_until
        # Persist to DB
        db.set_setting(f"cooldown_{email}", str(cooldown_until))
    
    def __init__(self):
        self._cooldowns = {}
        # Load persisted cooldowns
        for a in db.get_all_accounts():
            key = f"cooldown_{a['email']}"
            val = db.get_setting(key)
            if val:
                self._cooldowns[a['email']] = float(val)
    ```

3.6 SELECT_NEXT_MAILBOX IS ROUND-ROBIN, NOT HEALTH-AWARE [LOW]
    File: outreach_engine.py, lines 354-356
    ```python
    # Round-robin selection
    self._last_index = (self._last_index + 1) % len(candidates)
    return candidates[self._last_index]
    ```
    Problem: The comment says "health-aware round-robin" but it's just
    pure round-robin. It doesn't consider:
    - Bounce rate per account
    - Spam rate per account
    - Time since last used
    - Account health score
    
    This means a damaged account gets used just as often as a healthy one.
    
    FIX: Add health-weighted selection:
    ```python
    import random
    weights = [score_account_health(a) for a in candidates]
    total = sum(weights)
    if total > 0:
        pick = random.choices(candidates, weights=weights, k=1)[0]
        return pick
    # Fallback to round-robin
    self._last_index = (self._last_index + 1) % len(candidates)
    return candidates[self._last_index]
    ```

6. HOW TO TRICK SMTP SERVERS INTO THINKING YOU'RE MARKETING
================================================================================

Trick 1: The Unsubscribe Header (NOW FIXED ✅)
   The new commit added List-Unsubscribe headers. Gmail will now show
   the unsubscribe button. This is the #1 factor for inbox placement.

Trick 2: Send From a Dedicated Domain (Not Gmail)
   Gmail's algorithm penalizes @gmail.com sending to @company.com.
   
   Instead:
   1. Buy a cheap domain like getflinza.com ($12/year)
   2. Set up SPF, DKIM, DMARC records
   3. Create aliases: alex@getflinza.com, sarah@getflinza.com
   4. Route replies back to your Gmail via Cloudflare Email Routing
   5. Send FROM the custom domain
   
   This alone can DOUBLE your inbox placement rate.

Trick 3: Warm Up With Engagement, Not Just Volume
   Spam filters don't just look at volume — they look at engagement:
   
   Step 1: Send 10 test emails to your own addresses
   Step 2: OPEN them (load the tracking pixel)
   Step 3: REPLY to them with real text
   Step 4: Start sending to real leads
   
   Result: Gmail sees "this sender gets replies" → promotes your emails

Trick 4: Make Your Emails Look Like Newsletters
   Cold email pattern (BAD):
   "Hey, I saw your profile on LinkedIn and I think we should connect..."
   
   Newsletter pattern (GOOD):
   "Hi [Name], quick question about [Company]..."
   [Brief value proposition]
   "P.S. If this isn't relevant, just reply 'stop' and I won't follow up."
   [Physical address footer]
   
   Add this to your AI system prompt in config.py:
   ```
   Write like a marketing newsletter, not a cold sales email.
   Include a P.S. line and a physical address footer.
   Sound like a real person writing to a business owner.
   ```

Trick 5: The Seed Page Trick
   Every email should link to a landing page that:
   - Has your physical address (CAN-SPAM requirement)
   - Has a working unsubscribe form
   - Looks like a real marketing page (not a sales page)
   - Has social proof (testimonials, logos)

Trick 6: Feedback-ID Header (MISSING — Add This)
   Add this to email_sender.py after the unsubscribe headers:
   ```python
   msg["Feedback-ID"] = f"flinza:{from_email.split('@')[1]}"
   ```
   This tells Gmail to track your sender reputation. Without it, Gmail
   treats every send as anonymous — which hurts deliverability.

Trick 7: X-Precedence Header (MISSING — Add This)
   ```python
   msg["X-Precedence"] = "newsletter"
   ```
   This is a legacy header that tells mail filters "this is bulk mail,
   not spam." Spam filters still check for this.
